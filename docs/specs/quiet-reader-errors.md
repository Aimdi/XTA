# Quiet timeline and profile errors

The reader should remain calm when a read fails. Replace automatically visible
error text, emoji, and large panels in the X timeline/profile paths with a small
Retry control and an accessible information button. Tapping information opens
the failure explanation and the existing sign-in/diagnostics actions in a sheet.

Keep loaded posts visible, preserve reconnect/resume recovery, and keep known
rate-limit countdowns and disabled premature retries. A retry from the details
sheet closes it and retries once. Source chips that already open details should
show the details directly. Do not hide save, import, download, or other mutation
errors. Reuse translated labels; do not change the API or database layers.

Cover initial/next-page timelines, profile refreshes, profile replies, and shared
profile/media grids. Validate collapsed/default and expanded details behavior,
session actions, rate-limit controls, narrow/large-text layouts, and existing
read recovery regressions in CI. Ship as aimdi135 with the same signing identity
and a version code above every aimdi134 APK.
