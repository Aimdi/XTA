# Downloads center

Build on aimdi128. Keep existing XTA icons and compact surfaces. Add a single Downloads screen with active progress, completed files, retryable failures/interrupted jobs, and cancellation. Existing media download functions route through the same queue, retain their callbacks, and preserve Android's selected document folder or ask-every-time system picker.

Use a Flutter Triple Store with immutable entries. Serialize a bounded history (200 entries, 2 MB metadata limit) to application-support storage using a temp file and atomic rename. Pending work after restart becomes interrupted and retryable, never silently starts network activity. Enqueue must persist before starting. Stream HTTP response chunks into a private temp file; reject non-success HTTP responses and incomplete declared lengths. Close HTTP clients on cancellation, delete temp files after every terminal outcome, and avoid destination writes after a transfer was cancelled. Native document-tree copies stream off the Android UI thread and can abort/delete incomplete documents. Ask-every-time uses the system file picker with the staged file.

Show localized states, byte progress, retry, cancel, open-completed-file, clear-finished-history, and an informative empty state. No raw UI strings. Do not modify client/database, pinned dependencies, existing preferences, or existing API signatures. Only X image host pbs.twimg.com receives original-image URL normalization.

Batch photo downloads count actual successful destination saves, report exact saved/total results, and leave individual failures available in Downloads. No misleading success after one item out of many. Verify cancellation (including late network completion), stream/progress/length failures, atomic/restart persistence, queue ordering, retries, mixed batch counts, and native channel arguments with fake HTTP/platform dependencies. Flutter checks and APK build run through the pinned CI toolchain; real Android document providers remain a device test requirement.
